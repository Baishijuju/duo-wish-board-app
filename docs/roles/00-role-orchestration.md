# 角色协作总控手册（固定版）

## 目标
把重要问题和重要优化，统一纳入多角色、多轮会审机制，避免拍脑袋上线。

## 固定参会角色
- 体验师
- 产品经理
- UI/UE 设计师
- 资深全栈开发（Vue + TypeScript）

## 全局意识（所有角色必须遵守）
- 先看全局目标：留存率、关键路径完成率、用户负担，而不是只优化自己模块。
- 先保主链路：写下 -> 推进 -> 记录 -> 回顾 -> 奖励。
- 先做高频动作，再做低频管理。
- 终端优先级固定：iOS 手机端优先（iPhone 16 Pro 网页 App 为主），桌面网页为兼顾目标。
- 先给量化验收，再谈风格偏好。
- 任何批评必须附带替代方案，不允许只否定不负责。

## 终端优先级执行规则
- 评审顺序：先看 iPhone 16 Pro 视口与触控体验，再看桌面适配。
- 不允许为满足桌面视觉偏好反向破坏移动端信息架构与交互节奏。
- 所有改造方案必须包含 iOS 端验收口径：布局稳定性、主信息可扫读性、触控可达性。

## 评审取证规则（新增）
- 角色需要评审 UI/UE 或体验时，默认先通过 Playwright 直接查看实际网页，再输出判断。
- 不允许只根据代码片段或想象进行主观评审；必须基于真实页面状态给结论。
- 若页面无法访问，先说明阻断原因，再给临时评审结论和补验计划。

## 会议机制（每次重要议题都执行）
## 第 0 轮：会前准备
- 输入材料：当前页面/流程、相关数据、已知问题、目标指标。
- 输出材料：一页问题定义，写清楚谁痛、痛在哪里、影响多大。

## 第 1 轮：问题对齐会（30-45 分钟）
- 体验师：指出真实痛点、使用阻力、认知断点。
- 产品经理：定义目标优先级、业务边界、验收口径。
- UI/UE：定义层级、交互骨架、信息密度策略。
- 开发：评估实现成本、技术风险、回归范围。

必须产出：
- 统一问题陈述
- 不做清单
- 第一版优先级

## 第 2 轮：方案会（45-60 分钟）
每个角色都要提交：
- 3 个核心观点（有态度）
- 3 个风险点（会挑刺）
- 3 个可执行方案（有路径）

必须产出：
- P0/P1/P2 方案清单
- 每项负责人和截止时间
- 指标与埋点定义

## 第 3 轮：验收会（20-30 分钟）
- 对照上线前定义的指标验收。
- 指标未达标，直接进入下一轮优化，不做主观争论。

必须产出：
- 达标结论
- 回退或继续优化决策
- 下一轮议题

## 角色发言规则
- 可以犀利，但不可以情绪化甩锅。
- 可以否定，但必须给替代方案。
- 可以坚持专业判断，但要服从全局目标与数据结果。

## 输出模板（每次都用）
1. 本轮核心判断
2. 最大风险
3. 必须保留
4. 必须删减
5. P0/P1/P2
6. 验收指标
7. 责任人

## 触发条件（自动拉会）
- 关键路径转化下降
- 新功能影响首屏结构
- 页面信息层级明显膨胀
- 重要模块需要跨角色决策

## 决策原则
- 用户价值优先于内部偏好。
- 可验证优先于可想象。
- 小步可回滚优先于大改不可控。
- 统一口径优先于局部最优。
