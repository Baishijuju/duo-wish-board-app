# 双人人生愿望清单 产品经理方案（面向架构/研发）

> 角色前提：本文件以“手机 App 产品经理”视角撰写，目标是提升留存率，而不是单点美化。

## 1. 目标重述
当前产品最大优势是“关系感 + 记录感 + 情绪价值”。
当前最大风险是“结构偏重 + 默认信息过载 + 高频路径不够短”。

产品策略上，不建议推倒重做。建议做“保核心、砍负担、强闭环”的演进式改造。

## 2. 留存视角下的核心判断
### 2.1 为什么用户会留下
- 这是关系型产品，不是纯任务工具，天然具备情感复访动机。
- 有“写下 - 推进 - 领奖/回顾”的成长链路，容易形成连续行为。
- 文案与氛围有人格感，用户愿意把它当生活空间而非工具页面。

### 2.2 为什么用户会流失
- 首次和早期阶段负担大：默认看到的信息和控件太多，学习成本高。
- 高频动作不够短：需要多次识别层级后才能执行核心动作。
- 系统很强，但“看起来像后台”，与“轻陪伴”心智存在张力。

## 3. 产品北极星与指标体系（给数据埋点与研发）
## 3.1 北极星指标
- 双人有效推进率（7 日）：过去 7 天双方都至少完成 1 次有效推进/记录的空间占比。

## 3.2 关键过程指标
- 激活：新建愿望后 24 小时内完成首次推进的比例。
- 粘性：D1/D7 留存、周活跃天数（WAU depth）。
- 协同：双人互动率（留言、反应、共同推进占比）。
- 成就：星币获得到奖励兑现转化率。
- 负担：核心任务完成点击步数中位数、关键页面首屏可见控件数。

## 3.3 研发埋点建议（最低集）
- 页面首屏曝光：home/list/compose/review/space/detail。
- 高频动作：推进、留言发送、领取奖励、存入奖励、编辑愿望。
- 折叠动作：低频工具展开/收起、空间后页工具展开/收起。
- 中断点：进入页面后 30 秒无操作退出、表单未提交退出。

## 4. 该保留并升级的亮点（Do More）
## 4.1 必须保留
- 关系化叙事（双人视角、共同记录语气）。
- 愿望详情页的闭环主链路（看进度 -> 推进 -> 留下记录）。
- 回顾页的可视化复盘能力（热力图 + 统计）。
- 星币体系（但要降认知门槛，不要降存在感）。

## 4.2 升级方向
- 首页升级为“今日行动台”：只强调 1-2 个下一步动作。
- 详情页强化“当下一步”：将主要 CTA 稳定放在首屏固定区域。
- 回顾页增加“本周一句话总结 + 一键继续计划”。

## 5. 应考虑去掉或精简的部分（Do Less）
## 5.1 默认态精简原则
- 默认只展示高频；管理和配置全部后置。
- 同一屏最多一个主视觉模块，其他模块折叠或降级。
- 每个模块只允许一个主句 + 一个短副句。

## 5.2 建议直接收敛
- 空间页默认显露的筛选/排序控件数量，建议明显减少。
- 清单页条目中的重复状态信息，保留单主值 + 单副值。
- 长解释文案在列表态的出现频率，改为按需展开。

## 6. 信息架构建议（给架构同事）
## 6.1 两层结构替代多层嵌套
- 第一层：行动层（推进、记录、领取）。
- 第二层：管理层（编辑、校正、筛选、同步、备份）。

禁止在第一层嵌套第二层控件。

## 6.2 页面角色重定义
- 首页：分发动作，不承载重管理。
- 清单：快速浏览与进入详情，不做重筛选中心。
- 详情：单愿望的执行主战场。
- 空间：只在“管理模式”下承担系统级操作。

## 6.3 状态系统统一
- 统一主状态语义：进行中 / 可领取 / 待同步 / 已完成。
- 同一状态在各页使用同一颜色、同一文案模板、同一图标语义。

## 7. 交互与视觉的落地规范（给前端）
## 7.1 密度控制硬约束
- 首屏可见交互控件数建议 <= 8（移动端）。
- 同屏层级不超过 3 层。
- 列表项正文信息控制在两行内（主信息一行，副信息一行）。

## 7.2 CTA 优先级
- 每屏只允许一个主按钮样式（Primary）。
- 次要动作统一次级样式，危险动作固定折叠到低频区。

## 7.3 文案机制
- 主文案 <= 18 字，解释文案 <= 28 字（建议阈值）。
- 超阈值自动折叠，避免长句连排。

## 8. 研发实施优先级（分三期）
## P0（1-2 周，先保留存）
- 空间页默认态减重：只留领奖主流程，其他管理入口折叠。
- 清单页信息去重：单主值 + 单副值 + 单右侧状态位。
- 详情页主 CTA 稳位：推进动作在首屏始终可见。
- 埋点上线：完成最小事件集，打通漏斗看板。

## P1（2-4 周，增强复访）
- 首页改造为“今日行动台”，加入双人协同提醒。
- 回顾页增加周总结卡和下一步建议卡。
- 奖励路径优化：获得星币 -> 可领提示 -> 兑现操作缩短。

## P2（4-8 周，做增长机制）
- 双人激励机制：连续推进 streak、共同里程碑徽章。
- 轻提醒策略：不打扰但持续触达（节奏型提醒）。
- 个性化排序：按用户最近行为自动调整列表默认排序。

## 9. 技术与架构配合点
- 前端状态管理按“行动态/管理态”拆域，减少组件条件分支复杂度。
- 组件层做语义化：ActionCard、ManagePanel、StatusChip 统一规范。
- 设计 token 加入状态语义层，避免页面自行定义颜色口径。
- 事件总线或埋点 SDK 统一封装，避免页面散落埋点代码。

## 10. 风险与防回退
- 风险 1：过度精简导致高级用户找不到功能。
- 对策：默认折叠 + 明确管理模式入口，不删能力只降曝光。

- 风险 2：视觉简化后品牌感下降。
- 对策：保留情绪化文案语气与核心视觉符号（愿望瓶、热力图、星币）。

- 风险 3：改动多但无法验证收益。
- 对策：每期必须绑定指标目标和 A/B 或前后对照评估。

## 11. 建议的验收标准（Definition of Success）
- D7 留存相对提升 >= 10%。
- 新建愿望后 24h 首次推进率提升 >= 15%。
- 详情页推进动作点击步数中位数下降 >= 30%。
- 空间页首屏停留后无操作退出率下降 >= 20%。

## 12. 结论
这款产品不是缺功能，而是缺“默认态克制”。

后续改造应坚持一个原则：
把复杂能力藏到管理层，把高频动作提到行动层。

只要把这条执行到位，产品会同时得到两件事：
- 新用户更容易上手（降低流失）
- 老用户更愿意持续回来（提升留存）
