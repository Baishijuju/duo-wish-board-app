## 3. 回归场景
### 场景 A：成员当前余额对账
范围：
- 回顾页：星币 / 年 / 晨光
- 空间页：奖励中心默认态“手里星币”

预期：
- 回顾页期末余额 = 空间页当前手里星币

实测：
- 回顾页期末余额：24
- 空间页手里星币：24
- 结果：一致

### 场景 B：领奖统计视图可读性
范围：
- 回顾页：领奖 / 月 / 晨光

实测：
- 统计行数：4
- 首行文本：上班路上买一杯拿铁 / 次数 1 / 花费 4

结论：
- 领奖统计已改成“次数 + 花费”双指标对比，不再误导为单一进度条。

### 场景 C：详情页单愿望收益拆分
范围：
- 愿望详情：wish-a-morning-walk
- 愿望详情：wish-a-lunchbox-menu

实测：
- 早晨散步 20 次：已入账 4 枚 / 剩余可得 8 枚
- 做出 5 个不腻的便当组合：已入账 4 枚 / 剩余可得 3 枚

结论：
- 详情页当前展示已来自共享 selector，且已切出旧的“可领取”心智，改为实时结算口径。

## 5. 建议的后续回归清单
每次改星币模型后，最少复测以下 4 条：
1. 回顾页（星币 / 年 / 当前成员）期末余额 = 空间页“手里星币”
2. 空间页“现在可领”数量在推进、回退、领奖后三态变化正确
3. 详情页单愿望摘要在 count / steps / done 三类愿望上都成立，且只保留实时结算语义
4. 领奖统计中“次数 / 花费”两块不再被误读为完成进度
