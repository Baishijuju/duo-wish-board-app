# 另一台电脑接手指南

这份说明适用于从 GitHub 获取本项目，在另一台电脑上本地运行和继续开发。项目仓库：<https://github.com/Baishijuju/duo-wish-board-app>

## 一、先准备

1. 在新电脑安装 Git 和 Node.js。建议使用 Node.js 22 LTS。
2. 确认自己的 GitHub 账号有此仓库的访问权限。若仓库是私有仓库，需要先由仓库所有者授权。
3. 本项目的数据存放在 Supabase 云端，不在项目文件夹或 Git 历史中。登录应用时使用已有账号；不要把个人密码、验证码或访问令牌写进项目文件。

## 二、首次获取并启动

在 PowerShell、Windows Terminal 或 VS Code 终端运行：

```powershell
git clone https://github.com/Baishijuju/duo-wish-board-app.git
cd duo-wish-board-app
npm ci
Copy-Item .env.example .env.local
```

然后用 VS Code 打开 `.env.local`，把示例占位值替换成项目使用的 Supabase URL 和 Publishable Key：

```text
VITE_SUPABASE_URL=你的Supabase项目URL
VITE_SUPABASE_PUBLISHABLE_KEY=你的Supabase公开客户端Key
```

这些值可从 Supabase 项目设置中取得。`.env.local` 只保存在当前电脑，已被 Git 忽略，不要提交、发到聊天中或放进公共网盘。不要使用 `service_role`、数据库密码或其他服务端密钥作为前端配置。

启动本地开发服务器：

```powershell
npm run dev
```

浏览器打开 <http://localhost:3000>。停止服务时，在运行 Vite 的终端按 `Ctrl+C`。

## 四、日常开发

进入项目目录后：

```powershell
npm run dev
```

常用检查命令：

```powershell
npm run build       # 类型检查并生成生产构建
npm run test:unit   # 单元测试
npm run typecheck   # TypeScript/Vue 类型检查
```

完成修改后，先查看 `git status`，确认不要提交 `.env.local`、本机数据或生成文件，再正常提交并推送。另一台电脑获取之后的更新：

```powershell
git pull --ff-only origin main
npm ci
```

只有 `package-lock.json` 更新或依赖不一致时才需要重新运行 `npm ci`；平时拉代码后通常可以直接启动。

## 五、哪些会同步，哪些不会

- GitHub 保存源码、文档、迁移文件和依赖锁文件。提交并推送后，其他有权限的电脑可以克隆或拉取。
- Supabase 保存账号、共享空间和云端业务数据。它们不是 Git 文件；另一台电脑配置好客户端并用有权限的账号登录后，读取同一份云端数据。
- `.env.local`、浏览器登录状态、Git 凭据、Supabase CLI 登录凭据和本机 Wrangler 状态不会通过 Git 迁移，需在新电脑按需单独配置或登录。
- `node_modules/`、`dist/`、`.wrangler/` 是依赖、构建产物或本机缓存，不必复制。依赖用 `npm ci` 重建，构建产物用 `npm run build` 生成。
- `.env.production` 已在仓库中，供当前静态前端部署读取。前端 Publishable Key 属于公开客户端配置；绝不能把 Supabase 服务端密钥或数据库凭据放进任何 `VITE_*` 变量。

## 六、常见问题

- **克隆提示没有权限**：先确认 GitHub 账号已获仓库访问权限。使用 HTTPS 时按 GitHub 提示完成认证；不要把密码或令牌写进克隆 URL。
- **npm ci 失败**：确认 Node.js 和 npm 已安装且网络可访问 npm registry；可运行 `node -v`、`npm -v` 检查版本。
- **缺少 Supabase 配置或登录失败**：检查 `.env.local` 是否存在、变量名是否拼写正确、项目 URL/Publishable Key 是否来自正确的 Supabase 项目。修改环境变量后重启 `npm run dev`。
- **3000 端口被占用**：本项目要求使用 3000 端口。关闭占用该端口的其他开发服务后再启动。
- **开发看板显示空白或没有权限**：确认已登录正确的应用账号，并且该账号属于对应共享空间；不要用本地缓存或 Git 文件来替代云端数据。
