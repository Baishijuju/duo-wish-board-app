# P0 详细落地计划（开发执行版）v1

## 0. 计划目的
把 P0 从“方向”变成“可执行任务包”，确保产品、UI/UE、开发三方同步推进，按周可交付、可验收、可回滚。

## 1. 本轮范围（仅 P0）
- P0-1 空间页默认态减重
- P0-2 清单页条目骨架统一
- P0-3 详情页推进 CTA 固位
- P0-4 文案分层与折叠规则
- P0-5 最小埋点集上线

不包含：P1/P2 的增长能力、新玩法扩展、大范围视觉重绘。

## 2. 执行节奏（建议 7 天）
- Day 1：三方对齐 + UI 关卡 A + 技术方案冻结
- Day 2-4：P0-1/P0-2/P0-3 并行开发与联调
- Day 4-5：P0-4 文案折叠规则接入
- Day 5-6：P0-5 埋点与看板联调
- Day 7：UI 关卡 C + 回归测试 + 发布准备

## 3. 任务分解（可直接开工）
## TP0-1 空间页默认态减重
目标：首屏仅保留领奖主流程，管理能力后置。

涉及文件（预计）：
- src/pages/Settings.vue
- src/composables/useSpacePageState.ts
- src/style.css（如需补充密度 token）

实施步骤：
1. 梳理奖励中心首屏必留区块：可领、差额、快速存入。
2. 将筛选/排序/奖池编辑/同步备份迁移到“管理模式”容器。
3. 默认关闭管理容器，保留清晰入口。
4. 收敛首屏控件数量与层级。

UI/UE 输入：
- 空间页默认态与管理态结构图。
- 首屏主任务确认（唯一主动作）。

开发工时预估：1.0-1.5 人日

验收标准：
- 首屏控件数达到阈值。
- 首屏无操作退出率可跟踪且较基线下降。
- UI 走查通过主任务识别（10 秒规则）。

风险：
- 过度折叠导致高级用户找不到入口。

回滚点：
- 保留旧入口开关，可快速恢复到“默认展开”。

## TP0-2 清单页条目骨架统一
目标：四种排序下同骨架展示，去掉重复信息。

涉及文件（预计）：
- src/pages/List.vue
- src/composables/useListWishBoardState.ts
- src/style.css（如需统一状态位视觉）

实施步骤：
1. 固定条目骨架为“标题区 + 主副值 + 右侧状态位”。
2. 清理重复状态字段，只保留一组表达。
3. 对进度/星币/年龄/更新时间四种排序做同骨架映射。
4. 校验移动端断点下不换骨架。

UI/UE 输入：
- 四排序同骨架稿。
- 状态位优先级与视觉规范。

开发工时预估：1.0-1.5 人日

验收标准：
- 四种排序切换时结构不跳变。
- 条目信息行数稳定在约束范围。
- 进入详情点击率可跟踪。

风险：
- 不同排序信息密度差异导致文本溢出。

回滚点：
- 保留旧副信息展示函数，可按排序逐步迁移。

## TP0-3 详情页推进 CTA 固位
目标：用户进入详情后无需滚动即可执行推进。

涉及文件（预计）：
- src/pages/WishDetailAtelier.vue
- src/composables/useWishDetailPageState.ts
- src/style.css（若需 CTA 固位样式）

实施步骤：
1. 识别首屏区域内推进主 CTA 最优放置位。
2. 保证主 CTA 在不同进度模式下语义一致。
3. 将低频工具维持折叠并做视觉降权。
4. 补齐空态/异常态 CTA 呈现规则。

UI/UE 输入：
- CTA 优先级定义（每屏仅一个 Primary）。
- 低频工具降权规则。

开发工时预估：0.8-1.2 人日

验收标准：
- 推进动作点击步数中位数下降。
- 推进动作点击率提升。
- UI 走查确认首屏可达。

风险：
- 固位策略可能遮挡关键内容。

回滚点：
- 保留非固位布局样式类，支持开关切换。

## TP0-4 文案分层与折叠规则
目标：主句可扫读，长说明按需展开。

涉及文件（预计）：
- src/pages/List.vue
- src/pages/Settings.vue
- src/pages/WishDetailAtelier.vue
- src/style.css
- src/composables/*（仅在需要时提取文案展示 helper）

实施步骤：
1. 定义文案阈值规则（主句/副句）。
2. 为超阈值文本接入统一折叠交互（展开/收起）。
3. 统一关键页面的文案层级：主句 > 副句 > 补充。
4. 验证折叠组件在移动端可用性与可访问性。

UI/UE 输入：
- 文案层级规范与示例。
- 折叠组件交互规范。

开发工时预估：1.0-1.5 人日

验收标准：
- 首屏文本块数量下降。
- 页面间长文案策略一致。
- 用户“信息太多”主观反馈下降（通过调研或灰度反馈）。

风险：
- 过度截断导致语义缺失。

回滚点：
- 为每个模块保留禁用折叠配置。

## TP0-5 最小埋点集上线
目标：本轮优化可验证，形成下一轮决策依据。

涉及文件（预计）：
- src/App.vue（页面曝光挂点）
- src/pages/List.vue
- src/pages/Settings.vue
- src/pages/WishDetailAtelier.vue
- src/composables/*（交互事件触发点）
- 新增：src/utils/analytics.ts（建议）

实施步骤：
1. 定义事件模型：page_view / action_click / panel_toggle / abandon。
2. 封装统一上报入口（typed payload）。
3. 在 P0 涉及页面接入关键事件。
4. 联调并输出事件字典与校验样例。

UI/UE 输入：
- 关键交互触点定义（哪些动作代表可用性改善）。

开发工时预估：1.0-1.5 人日

验收标准：
- 看板可见核心漏斗。
- 关键路径事件链完整。
- 可按页面和模块拆分分析。

风险：
- 事件口径不统一，影响数据可用性。

回滚点：
- 通过开关关闭新埋点上报，不影响业务功能。

## 4. 依赖与并行关系
可并行：
- TP0-1（空间页）与 TP0-2（清单页）可并行。
- TP0-3（详情页）可与 TP0-4 并行部分推进。

串行依赖：
- TP0-5 建议在 TP0-1~TP0-4 关键交互定稿后接入，避免重复埋点。

门禁依赖：
- 每个任务包进入开发前必须通过 UI 关卡 A。
- 每个任务包发布前必须通过 UI 关卡 C。

## 5. 人员分工建议
- 产品经理：目标、边界、验收指标、灰度决策。
- UI/UE：骨架稿、交互规范、验收走查。
- 前端开发：页面改造、组件复用、埋点接入。
- 后端/数据支持：埋点入库与看板配置（如当前架构需要）。
- 测试：关键路径回归、移动端断点回归、埋点校验。

## 6. 回归清单（发布前必跑）
- 清单页：四排序切换 + 条目点击进入详情。
- 空间页：默认态、管理态切换、领奖主流程。
- 详情页：推进动作、低频工具折叠、异常态展示。
- 全局：移动端布局、长文案折叠、主题一致性。
- 数据：页面曝光、动作点击、折叠事件、退出中断事件完整。

## 7. 风险雷达
- 需求漂移：中途新增非 P0 项导致延期。
- 视觉返工：UI 稿未冻结就进开发。
- 数据失真：埋点命名或口径中途变更。
- 体验回退：信息减重后误伤老用户习惯。

应对：
- 锁 scope、锁稿、锁口径、灰度发布。

## 8. 发布与复盘
发布策略：
- 小流量灰度 -> 核心指标观察 -> 全量。

复盘时间：
- 上线后 3-5 天输出首轮复盘。

复盘输出：
- 指标变化（点击步数、退出率、关键动作完成率）。
- 用户反馈（主观“是否更清晰”）。
- 下一轮进入 P1 的建议与排期。
